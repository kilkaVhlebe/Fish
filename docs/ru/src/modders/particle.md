# Типы частиц

`fish_api::particle` регистрирует типы частиц: серверную половину частицы — id и число, которым могут пользоваться
пакеты.

```rust
use fish_api::particle::Particles;

fn init() -> Result<(), fish_api::Error> {
    let sparkle = Particles::register("content_demo:ruby_sparkle")?;
    // Particles::register_with(id, true) рисует её, даже если игрок выбрал минимум частиц.
    let _ = sparkle;
    Ok(())
}
```

- **`Particles::register(id)`** / **`register_with(id, always_show)`** регистрируют тип (`namespace:path`, пространство
  имён — id мода) и возвращают `ParticleType`.
- **`ParticleType::raw_id()`** — его числовой id в реестре Fish `fish:particle_types`. Он синхронизируется с сервером
  для модов, работающих на обеих сторонах, поэтому при входе на сервер перенумеровывается: спрашивайте его во время
  игры и не сохраняйте.

`assets/<id мода>/particles/<path>.json` мода (список текстур, как в ресурспаке) и его текстуры в
`assets/<id мода>/textures/particle/` копируются в папку контента; загрузчик предупреждает, если описания нет.

```json
{ "textures": ["content_demo:ruby_sparkle"] }
```

## Правила

- **Регистрация** разрешена, пока выполняются `pre_launch` или `main`; повторная регистрация типа даёт
  `ALREADY_EXISTS`.

## Ограничения

- Частицы Horizon — закрытый набор, который он рисует сам: у типа мода **пока нет клиентской фабрики**, поэтому для него
  ничего не рисуется и нет вызова, который бы его породил. И то и другое придёт с фазой рендеринга (P10, фабрики частиц).
- Тестирование: ожидание `particles` из [Тестирования модов](testing.md).
