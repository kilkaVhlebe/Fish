# Игровые правила

`fish_api::game_rule` добавляет правила в `/gamerule`: логическое, целое, дробное или одно из именованных значений, у
каждого есть категория и значение по умолчанию. У каждого мира свои значения, игра сохраняет их вместе с миром.

```rust
use fish_api::game_rule::{Category, GameRules};

fn init() -> Result<(), fish_api::Error> {
    let sparkles = GameRules::register_bool("mymod:sparkles", Category::Misc, true)?;
    let limit = GameRules::register_int("mymod:limit", Category::Mobs, 8, 0, 64)?;
    let scale = GameRules::register_double("mymod:scale", Category::Drops, 1.0, 0.0, 10.0)?;
    let mode = GameRules::register_enum("mymod:mode", Category::Misc, "normal", &["easy", "normal", "hard"])?;

    GameRules::on_change("mymod:limit", |c| log::info!("limit {:?} -> {:?} в {}", c.old, c.new, c.world))?;

    // позже, в любом обработчике события игры с миром:
    if sparkles.get()? && limit.get()? > 4 {
        limit.set(4)?;
    }
    Ok(())
}
```

- **Имена** вида `namespace:path`. Пространство `minecraft` принадлежит игре и отклоняется.
- **Категории**: `Player`, `Mobs`, `Spawning`, `Drops`, `Updates`, `Chat` и `Misc`: собственные группы игры.
- **Регистрация** разрешена, пока выполняется `pre_launch` или `main`, с той же заморозкой, что у [реестров](registry.md);
  поздний вызов возвращает `registries are frozen`. Повторное имя даёт `ALREADY_EXISTS` (правило остаётся за первым
  модом); неверное описание (перевёрнутые границы, значение по умолчанию вне границ, пустой или повторяющийся вариант)
  даёт `INVALID_ARGUMENT`, загрузчик пишет причину. Варианты состоят из букв, цифр, `_`, `-` и `.`: игрок набирает их в
  команде.
- **`get` и `set`** работают с миром той игры, чьё событие выполняется (любое событие, у которого есть игра: такты,
  взаимодействия, команды, клавиши, HUD). Вне события мира нет: `get` отвечает значением по умолчанию, `set` возвращает
  `UNSUPPORTED`. `GameRules::get(name)` / `GameRules::set(name, Value)` доступны для правила любого мода по имени;
  типизированные ручки (`BoolRule`, `IntRule`, `DoubleRule`, `EnumRule`) возвращает `register_*`. Значение другого типа
  даёт `TYPE_MISMATCH`, вне границ или не из вариантов даёт `INVALID_ARGUMENT`.
- **Обратные вызовы изменения** (`GameRules::on_change`, либо `game_rule::CHANGED_EVENT` для всех правил) срабатывают
  после изменения значения: командой `/gamerule`, экраном правил или модом. Установка уже действующего значения ничего
  не вызывает.

## В игре

`/gamerule <namespace:path> [<значение>]` показывает или меняет правило со штатными сообщениями игры и с уровнем доступа
`/gamerule` (2). Дерево команд строится вместе с правилами, поэтому автодополнение и подсветка в чате их знают:
логическое правило принимает `true`/`false`, целое и дробное принимают число в границах (значение вне границ отвергает
разбор), у enum дополняются варианты. Результат команды (`/execute store`): 0 или 1 для логического, значение для
целого, усечённое значение для дробного и номер варианта для enum.

В «Параметры мира» > «Игровые правила» правила модов перечислены в своих категориях после правил игры: переключатель
для логического, поле для целого и дробного, кнопка, перебирающая варианты enum. «Готово» записывает изменённые (без
сообщения в чат: его даёт `/gamerule`).

## Сохранение

Файл игры `data/minecraft/game_rules.dat` не трогается: ванильная игра отвергает файл с незнакомыми ключами. Fish хранит
свои правила рядом, в своём пространстве имён, в `<мир>/data/fish/game_rules.json`:

```json
{ "schema": 1, "rules": { "mymod:limit": 4, "mymod:mode": "hard" } }
```

Пишутся только значения, отличные от значения по умолчанию (если отличий нет, файл удаляется). Значения правил, которых
больше никто не регистрирует, сохраняются как были, так что временно убранный мод ничего не теряет; значение, не
подходящее правилу (тип, границы), игнорируется с предупреждением. Правила читаются при открытии мира и пишутся при его
сохранении. У мира без Fish нет такого файла, всё по умолчанию; после удаления Fish сохранение читается ванильной
игрой как раньше.

## Тестирование

В скриптах `cargo fish test` есть два ключа, а `expect.gamerules` читает значения:

```toml
[[step]]
gamerule = { name = "mymod:limit", value = 12 }     # /gamerule в текущем мире
[step.expect]
command_feedback = ["Gamerule mymod:limit is now set to: 12"]
gamerules = { "mymod:limit" = 12, "mymod:sparkles" = true }

[[step]]
world = "other"            # сохраняет правила этого мира на диск, открывает другой и читает его правила
[step.expect]
gamerules = { "mymod:limit" = 8 }
```

`gamerule` без `value` читает правило. Шаг со значением вне границ или не того типа пишет причину в `command_feedback` и
оставляет значение. В Rust то же делают `TestHost::gamerule`, `game_rule`, `game_rule_defs`, `switch_world` и
`close_world`; `sim.world = None` — главное меню. См. `examples/mods/gamerule-demo`.

## Ограничения

- У клиента на **удалённом сервере** своего мира нет: его `get` отвечает значениями по умолчанию, `set` не работает.
  Значениями владеет Fish сервера (если на нём есть мод); на клиент Fish их пока не синхронизирует, а экран игровых
  правил такого клиента показывает только правила игры.
- Экран правил **«Создать мир»** показывает только правила игры: новый мир начинается со значений по умолчанию, меняет
  их `/gamerule`. Экран открытого мира, который запускает эта игра, показывает и правила Fish.
- Дерево команд строится один раз при первом использовании, уже после загрузки Fish: правила надо регистрировать, пока
  выполняются точки входа (позже регистрировать всё равно нельзя).
- Категории — семь игровых, своих нет.
- Значения сохраняются, когда игра сохраняет мир, и читаются при его открытии; мир, открытый в двух играх одного
  процесса (окно и встроенный сервер), делит один набор значений.
