# Звуковые события

`fish_api::sound` регистрирует звуковые события, которые описывают ресурсы мода, и проигрывает их в окне игрока.

Файлы лежат в архиве мода точно так же, как в ресурспаке:

```text
assets/content_demo/sounds.json           {"ruby_chime": {"sounds": ["content_demo:ruby_chime"], "subtitle": "..."}}
assets/content_demo/sounds/ruby_chime.ogg  Ogg Vorbis, моно для звука, который идёт из точки
```

```rust
use fish_api::event::lifecycle;
use fish_api::sound::Sounds;

fn init() -> Result<(), fish_api::Error> {
    let chime = Sounds::register("content_demo:ruby_chime")?;
    lifecycle::client::END_TICK.register(move |c| {
        let client = c.client();
        if let Ok(Some(p)) = client.player() {
            let _ = chime.play_at(&client, [p.x, p.y, p.z], 1.0, 1.0);
        }
    })?;
    Ok(())
}
```

- **`Sounds::register(id)`** регистрирует событие (`namespace:path`, пространство имён — id мода) и возвращает
  `SoundEvent`. Событие получает и числовой id в реестре Fish `fish:sound_events`, который синхронизируется с сервером,
  как любая запись [реестра](registry.md).
- **`SoundEvent::play(client, volume, pitch)`** проигрывает его у слушателя, **`play_at(client, pos, volume, pitch)`** —
  в точке мира. Громкость и высота в `(0, 10]`, 1 — обычные.
- **`Sounds::play(client, id, pos, volume, pitch)`** проигрывает любое известное игре событие, мода или ванильное
  (`minecraft:entity.experience_orb.pickup`).

## Правила

- **Регистрация** разрешена, пока выполняются `pre_launch` или `main`; повторная регистрация события даёт
  `ALREADY_EXISTS`.
- Загрузчик копирует `assets/` мода в его папку контента (см. [блоки](block.md)), так что Horizon читает `sounds.json`
  мода вместе с ванильным. Когда точки входа закончились, он предупреждает, если `sounds.json` не называет
  зарегистрированное событие или названного в нём файла нет.

## Где играет звук

Звуки играют на клиенте собственного окна игрока. У сервера нет звука: проигрывание там возвращает `UNSUPPORTED`.
События взаимодействия предметов и блоков выполняются на (встроенном) сервере, поэтому мод, которому нужен звук на
клик, запоминает это и проигрывает звук на следующем тике окна, как делает `content-demo`. Событие, которого игра не
знает (нет ресурсов), даёт `NOT_FOUND`.

## Ограничения

- Пока нельзя проиграть звук на клиентах других игроков (для этого нужен звуковой пакет события мода).
- Звуки фиксируются на время запуска: перезагрузка ресурспаков перечитывает `sounds.json`, но регистрировать можно
  только при загрузке.
- Тестирование: ожидания `sounds` и `played_sounds` из [Тестирования модов](testing.md); симулированное окно знает
  события файлов `sounds.json` в папках контента.
