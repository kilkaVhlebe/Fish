# Обзор архитектуры

## Решения

- **Модель внедрения: Fish Edition + рантайм-моды.** CI Fish собирает клиент Horizon из исходников на
  зафиксированном коммите и внедряет хуки на этапе сборки через *horizon-mixins* — официальный
  инструмент Horizon для миксинов исходников. Моды — нативные динамические библиотеки, которые
  загружаются при старте игры через стабильный C ABI. Игрокам ничего не нужно компилировать.
  Бинарное патчирование официального exe на лету отвергнуто (thin-LTO, один codegen unit,
  приватные символы, частые nightly).
- **Интеграция с лаунчером** только через публичный CLI `horizon-launcher`. Установщик создаёт
  экземпляр и задаёт его *wrapper* — `fish-launch`. Fish не пишет в файлы лаунчера.
- **Платформы:** сначала Windows; Linux в CI с P0; macOS в P16.
- **Документация:** rustdoc/справочник API на английском; руководства и дорожная карта на английском и русском.
- **Toolchain:** Rust 1.99.1, edition 2024. Лицензия MIT.
- **Версионирование ABI:** major 0 до первого публичного релиза; затем minor хоста >= minor мода.
- **Имена:** каталог данных `fish-loader`, переменные `FISH_LOADER_*` (без конфликта с оболочкой fish).

## Базовые контракты

- `fish.toml` — единый источник правды о версиях, пинах, порогах покрытия, адресе релизов.
- Моды — zip-архивы `.fish` (или каталоги) с манифестом `fish.mod.toml` и библиотеками в `bin/<platform>/`.
- ABI — таблицы `#[repr(C)]`, версионируются полем `size`, функции только добавляются; паники не
  пересекают границу; память освобождает тот, кто её выделил.
- События идентифицируются `namespace:path`, имеют фазы и режимы объединения (аналог Fabric `Event<T>`).
